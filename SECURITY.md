# Security Policy

## Supported Versions

Security fixes are considered for the current `main` branch. This educational
project does not maintain a formal long-term support policy for tagged or
historical versions.

## Reporting a Vulnerability

Please use [GitHub Private Vulnerability Reporting](https://github.com/jonatadev/BoletoPaymentLab/security/advisories/new)
to report a suspected vulnerability. Do not publish vulnerability details in a
public GitHub issue, discussion, pull request, or commit.

## What to Include

Include the following information where available:

- A clear vulnerability description.
- Affected components, versions, endpoints, or configurations.
- Reproduction steps or a minimal proof of concept.
- The potential impact.
- Relevant logs or evidence with passwords, tokens, personal data, and other
  secrets removed.

## Disclosure Process

Reports are reviewed and validated before remediation work begins. The project
maintainers may request clarification or additional evidence. A coordinated
disclosure approach will be discussed with the reporter after the report is
triaged; no response or remediation deadline is guaranteed.

## Security Scope

Boleto Payment Lab is an educational software engineering project using
synthetic data. It must not be assumed production-ready or suitable for real
financial processing without an independent security, compliance, operational,
and threat-model review.
